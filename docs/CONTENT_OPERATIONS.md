# Threads 자동운영 P2

## 사용할 수 있는 흐름

1. **Planner**에서 사업/계정, 이번 주 목표, 독자, 목표 게시 수(1~30), 기간을 입력한다.
2. 콘텐츠 믹스를 합계 100%로 조절한다. 가장 큰 나머지 방식으로 정확한 개수만큼 카테고리를 배분하고 섞는다.
3. 주간 계획을 생성하고 주제·카테고리를 수정한다. **전체 글 생성**으로 계획 순서에 맞춘 실제 Threads 본문을 만든다.
4. 글을 편집하고 **이번 주 자동 시간 배분**을 누른다. KST 시간대·하루 상한과 기존 예약을 반영하며, 같은 카테고리의 반복 슬롯을 우선 사용한다. 부족한 시간대는 사용자에게 알려준다.
5. 글과 시간을 검토했다고 체크한 뒤 **Calendar + Queue 전체 배치**한다. 기존 AI 결과와 drafts를 한 트랜잭션으로 연결하며 일부만 저장되지 않는다.
6. **Calendar**에서 월간/주간·상태/카테고리 필터로 확인한다. 카드 클릭은 기존 Composer 상세 편집, 게시 전 카드 드래그는 예약 시간 변경이다. 게시된 글과 게시 중 글은 이동하지 않는다.
7. **반복 스케줄**에서 매일/평일/주말/선택 요일, KST 시각, 카테고리, 콘텐츠 유형, 기본/사용자 템플릿을 등록한다. 규칙은 계속 표시되는 슬롯이며 실제 글과 분리한다. 빈 슬롯은 점선으로 보인다.
8. **빈 슬롯 채우기**는 해당 기간의 목표에서 실패하지 않은 기존 예약 수를 빼고 부족한 개수의 주제를 제안한다. 기존 본문을 AI에 중복 회피 소재로 전달한다. 검토하지 않은 글을 자동으로 Queue에 넣지 않는다.
9. Dashboard의 오늘 예정·다음 게시·주간 목표/준비/게시/부족·카테고리 구성과 빠른 버튼, **Analytics**의 실제 DB 집계를 사용한다.

반복 슬롯은 동일한 글을 무검토로 재게시하는 기능이 아니다. 계획/콘텐츠 검토 후 슬롯에 배치한 각각의 글은 기존 자동 게시 실행기가 처리한다. 무인 AI 생성·자동 승인 모드는 이번 단계에 포함하지 않는다. Meta 토큰이 없으면 AI 생성/DB 저장/배치는 가능하고 실제 Threads 게시만 대기한다.

## DB

- `content_categories`: workspace, 이름/색, 작성자, 제외 시각. 기본 12종과 사용자 분류. `drafts.category_id`와 workspace 복합 FK로 연결한다. 삭제는 숨김이며 과거 글의 분류는 남는다.
- `content_plans`: 사업/목표/독자/기간/목표 수/100% 믹스/편집 가능한 항목/진행 상태/수정 버전. AI 결과 ID와 실제 draft ID를 항목에 저장한다.
- `recurring_schedules`: 요일 배열/KST 시각/기간/콘텐츠 유형/템플릿/카테고리/운영 여부.
- `recurring_occurrences`: 반복 규칙, 실제 예정 시각과 생성된 draft. 동일 슬롯의 중복 연결을 방지한다. 취소하거나 이동한 슬롯은 다음 글에 재사용할 수 있다.
- `draft_insights`: 실제 Meta 지표 수신을 위한 nullable 필드(조회·좋아요·답글·재게시·인용·참여율·팔로워 변화·수집 시각). 아직 수집하지 않고 fake 값을 넣지 않는다.
- 새 공개 테이블은 기존 workspace membership helper의 RLS를 사용한다. 식별자/workspace/작성자 변경 권한을 주지 않고 새 기능에 필요한 컬럼만 쓰게 한다. Insights는 멤버 읽기만 허용한다.
- `save_categorized_posts`는 기존 저장·게시 엔진을 감싼 카테고리 연결이다. `place_content_plan`은 버전·AI 소스·카테고리·예약 충돌을 검증하고 원자적으로 저장한다.

## 집계 기준

게시·날짜·시간대·카테고리·계정 차트는 선택 기간에 성공한 글 기준이다. 실패는 시도 시각(없으면 수정 시각), 예약은 예정 시각 기준이다. 예약 실행률은 기한이 지난 예약 중 성공 비율이며 대상이 없으면 ‘—’로 표시한다. AI 비율은 AI 결과와 실제 draft 연결로 계산한다. Threads 반응 지표는 **Threads Insights 연결 후 제공**으로 표시한다.

기존 Auth/Session/Workspace 정책, Threads API 게시/자동 실행 엔진과 MASTER_PLAN은 변경하지 않았다. OpenAI 서버 설정은 P1의 환경변수/Vault 설정을 재사용한다.
